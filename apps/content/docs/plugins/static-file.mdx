## Installation

```package-install
npm install @orpc/node@beta
```

## Setup

Use `StaticFileHandlerPlugin` to serve a directory alongside your procedures. Files are only served when no procedure matches a `GET` or `HEAD` request, so procedures always take precedence.

```ts
import { StaticFileHandlerPlugin } from '@orpc/node'
import { RPCHandler } from '@orpc/server/node'

const handler = new RPCHandler(router, {
  plugins: [
    new StaticFileHandlerPlugin({
      /**
       * The directory files are served from. Resolved against the working
       * directory when relative.
       */
      rootDir: './public',

      /**
       * The URL path files are served under, appended to the handler prefix
       * when one is set.
       *
       * @default '/'
       */
      path: '/',

      /**
       * The file served when the request path resolves to a directory.
       * Set to `false` to disable directory index files.
       *
       * @default 'index.html'
       */
      indexFile: 'index.html',

      /**
       * A file served with status 200 when no file matches the request path,
       * relative to `rootDir`. Useful for single page application routing.
       *
       * @default undefined
       */
      fallbackFile: 'index.html',

      /**
       * The `Cache-Control` response header value. Set to `false` to omit the header.
       *
       * @default 'public, max-age=0'
       */
      cacheControl: 'public, max-age=0',

      /**
       * Whether files and directories whose name starts with a dot can be served.
       * When disabled, names shaped like 8.3 short names, such as `ENV~1`, are
       * refused too, since NTFS and FAT resolve them to dotfiles.
       *
       * @default false
       */
      dotfiles: false,

      /**
       * Serves compressible files in an encoding the client accepts, from
       * precompressed sidecars and optionally from copies compressed on demand.
       * Omit to always serve files as they are. See Compression below.
       *
       * @default undefined
       */
      compression: undefined,

      /**
       * Whether symbolic links whose target lies outside `rootDir` can be served.
       * Enabling this exposes every file those links reach.
       *
       * @default false
       */
      allowSymlinks: false,

      /**
       * Extra content types keyed by lowercase file extension without the dot,
       * merged over the built-in detection. Unrecognised extensions are served
       * as `application/octet-stream`.
       */
      mimeTypes: {},
    }),
  ],
})
```

Responses carry [ETag](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/ETag) and [Last-Modified](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Last-Modified) headers, so unchanged files revalidate as `304 Not Modified`, and [range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests) are answered with `206 Partial Content` for media seeking and resumable downloads.

:::info
The `handler` can be any supported oRPC handler, such as [RPCHandler](/docs/rpc/handler), [OpenAPIHandler](/docs/openapi/handler), or a custom one.
:::

:::warning
`rootDir` should contain only files you intend to make public. Requests cannot escape it through `..` segments or symbolic links, but every file inside it is reachable.
:::

## Compression

Set `compression` to serve compressible files, such as HTML, CSS, JavaScript, JSON, and SVG, in an encoding the client accepts through its [Accept-Encoding header](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Accept-Encoding). An encoded file comes from one of two sources, tried in order:

1. **A precompressed sidecar** next to the file, such as `app.js.br`, `app.js.zst`, or `app.js.gz`, usually written by your build. Sidecars are served as soon as `compression` is set, so on its own it never compresses anything.
2. **A copy compressed on demand** into `cacheDir`, once you set it and no sidecar provides an accepted encoding. The first request for a file in an encoding compresses it and is answered with the copy. Later requests, after a restart too, are served straight from that copy, so each file is compressed only once per encoding.

```ts
const handler = new RPCHandler(router, {
  plugins: [
    new StaticFileHandlerPlugin({
      rootDir: './public',
      compression: {
        /**
         * The encodings files can be served in, prioritized by their order and
         * only applied if the client supports them. Applies to both sidecars and
         * compression into `cacheDir`.
         * Supported values: 'br' | 'zstd' | 'gzip'
         *
         * @default ['br', 'zstd', 'gzip']
         */
        encodings: ['br', 'zstd', 'gzip'],

        /**
         * Whether precompressed sidecar files next to a file are served. Disable
         * it when your build writes none, to skip looking for them on every request.
         *
         * @default true
         */
        precompressed: true,

        /**
         * The directory files are compressed into when no sidecar provides an
         * accepted encoding, created on first use.
         *
         * @default undefined (only sidecars are served)
         */
        cacheDir: './.cache/static-file',

        /**
         * The minimum file size in bytes required to compress a file into
         * `cacheDir`. Sidecars are served whatever their size.
         *
         * @default 1024 (1KB)
         */
        threshold: 1024,
      },
    }),
  ],
})
```

Encoded files carry their own `ETag` and `Content-Length`, so conditional and range requests keep working, and every response that could be encoded carries [Vary](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Vary)`: Accept-Encoding`.

In `cacheDir`, a copy is keyed by the file's real path, size, and modification and change times, so an edited or replaced file is compressed again rather than served stale. A copy that comes out no smaller than its file is never served, and a file whose copy cannot be written is served uncompressed instead of failing the request. Old copies are never removed, so you can clear the directory whenever you like, such as on every deploy. Compressing into `zstd` requires Node.js 22.15 or later; older versions skip it there and still serve `zstd` sidecars.

:::warning
Use a `cacheDir` that nothing else writes to, since its copies are served as the compressed form of your files, and keep it outside `rootDir` so the copies are not reachable as files of their own.
:::

To compress responses on every request instead, add the [Response Compression Plugin](/docs/plugins/response-compression). It skips anything already encoded, so sidecars and cached copies are served as they are, and it leaves `206 Partial Content` responses alone so range requests keep working.

```ts
import { ResponseCompressionHandlerPlugin } from '@orpc/server/plugins'

const handler = new RPCHandler(router, {
  plugins: [
    new StaticFileHandlerPlugin({ rootDir: './public', compression: {} }),
    new ResponseCompressionHandlerPlugin(),
  ],
})
```

:::tip
Precompressing assets at build time costs nothing per request and compresses best, since it can use the slowest levels.
:::
