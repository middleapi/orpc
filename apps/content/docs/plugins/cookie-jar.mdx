Clients outside a browser, such as during server-side rendering, in scripts, or in tests, do not keep cookies. `CookieJarLinkPlugin` stores the cookies servers set and sends them back on later requests, following the same rules as a browser. Browsers handle cookies themselves and do not need it.

## Setup

```ts
import { CookieJarLinkPlugin } from '@orpc/client/plugins'

const link = new RPCLink({
  origin: 'https://api.example.com',
  plugins: [
    new CookieJarLinkPlugin({
      origin: 'https://api.example.com', // <- optional, enables browser `Domain` and `Secure` checks
    }),
  ],
})
```

:::info
The `link` can be any supported oRPC link, such as [RPCLink](/docs/rpc/link), [OpenAPILink](/docs/openapi/link), or a custom one.
:::

:::warning
Cookies belong to the link, like a browser profile belongs to one user. On a server, do not share a link between users: create a client per request, or use a [per-request jar](#per-request-jar).
:::

A `cookie` header you set yourself, for example through the link's `headers` option, is kept and wins over jar cookies with the same name.

## Custom Jar

Pass your own `CookieJar` to read, clear, or share cookies between links:

```ts
import { CookieJar, CookieJarLinkPlugin } from '@orpc/client/plugins'

const jar = new CookieJar()

const link = new RPCLink({
  plugins: [new CookieJarLinkPlugin({ jar })],
})

jar.getCookies() // <- stored cookies
jar.clear()
```

## Per-Request Jar

`jar` also accepts a function, so one link can keep a jar per user:

```ts
const link = new RPCLink<{ jar: CookieJar }>({
  plugins: [
    new CookieJarLinkPlugin({
      jar: ({ context }) => context.jar,
    }),
  ],
})
```

:::warning
With the [Batch Plugin](/docs/plugins/batch), the function receives the batch request's context, so keep users in separate batches with `scope`.
:::
