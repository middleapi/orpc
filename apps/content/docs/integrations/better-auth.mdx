:::warning
This guide assumes familiarity with [Better Auth](https://better-auth.com/). Review the official documentation if needed.
:::

The integration provides middlewares that resolve the Better Auth session and add it to the context, typed from your auth instance.

## Installation

```package-install
npm install @orpc/better-auth@beta better-auth
```

## Setup

The integration requires the [Request Headers Plugin](/docs/plugins/request-headers) and the [Response Headers Plugin](/docs/plugins/response-headers). The middlewares read the session from `context.reqHeaders` and append the cookies Better Auth sets, such as a refreshed session cookie or the [cookie cache](https://better-auth.com/docs/concepts/session-management#cookie-cache), to `context.resHeaders`.

```ts
import type { RequestHeadersHandlerPluginContext, ResponseHeadersHandlerPluginContext } from '@orpc/server/plugins'
import { os } from '@orpc/server'
import { RequestHeadersHandlerPlugin, ResponseHeadersHandlerPlugin } from '@orpc/server/plugins'

interface ServerContext extends RequestHeadersHandlerPluginContext, ResponseHeadersHandlerPluginContext {}

const base = os.$context<ServerContext>()

const handler = new RPCHandler(router, {
  plugins: [
    new RequestHeadersHandlerPlugin(),
    new ResponseHeadersHandlerPlugin(),
  ],
})
```

:::info
The `handler` can be any supported oRPC handler, such as [RPCHandler](/docs/rpc/handler), [OpenAPIHandler](/docs/openapi/handler), or a custom one.
:::

## Protected Procedures

`requireSession` adds the session to the context, or throws an `UNAUTHORIZED` error when the request has none. `optionalSession` adds the session, or `null`:

```ts
import { optionalSession, requireSession } from '@orpc/better-auth'
import { auth } from './auth'

const router = {
  me: base
    .use(requireSession({ auth }))
    .handler(({ context }) => context.session.user),

  greeting: base
    .use(optionalSession({ auth }))
    .handler(({ context }) => `Hello, ${context.session?.user.name ?? 'guest'}`),
}
```

`context.session` is `typeof auth.$Infer.Session`, so fields added by plugins or `additionalFields` are typed too. Only a missing session becomes `UNAUTHORIZED`; other errors from `getSession` propagate to oRPC's [error handling](/docs/error-handling).

`auth` also accepts a function, sync or async, that receives the middleware options and input. Use it when the instance lives in the context:

```ts
const procedure = os
  .$context<ServerContext & { auth: typeof auth }>()
  .use(requireSession({ auth: ({ context }) => context.auth }))
```

## Permissions

To check the permissions of Better Auth's [access control](https://better-auth.com/docs/plugins/admin#access-control), wrap `requireSession` with `os.middleware` and extend it with `.use`, which sees `context.session`:

```ts
import { requireSession } from '@orpc/better-auth'
import { ORPCError, os } from '@orpc/server'
import { auth } from './auth'

function requirePermission(permissions: Record<string, string[]>) {
  return os
    .middleware(requireSession({ auth }))
    .use(async ({ context, next }) => {
      const { success } = await auth.api.userHasPermission({
        body: { userId: context.session.user.id, permissions },
      })

      if (!success) {
        throw new ORPCError('FORBIDDEN')
      }

      return next()
    })
}

const router = {
  listUsers: base
    .use(requirePermission({ user: ['list'] }))
    .handler(async () => {
      // ...
    }),
}
```

Unauthenticated calls get `UNAUTHORIZED` before any permission check. `userHasPermission` comes from the [admin plugin](https://better-auth.com/docs/plugins/admin). With the [organization plugin](https://better-auth.com/docs/plugins/organization), call `auth.api.hasPermission({ headers: context.reqHeaders, body: { permissions } })` instead, which checks the member's role in the active organization. Create the middleware with `base.middleware` instead of `os.middleware` so `context.reqHeaders` is typed.

## Deduplication

When the session middlewares run more than once for the same request, such as chained middlewares or a procedure that [calls](/docs/client/server-side) another one with the same context, the session is looked up only once (see [Dedupe Middleware](/docs/recipes/dedupe-middleware)). The lookup is stored on `context.reqHeaders` and reused while its values stay the same. A failed lookup is not reused. Each [batch](/docs/plugins/batch) sub-request has its own `reqHeaders`, so it looks up the session on its own.

Set `dedupe: false` to look up the session on every call, so a sign-out or an expired session is noticed on the next call. Use it when one `reqHeaders` outlives a request, such as the headers of a [WebSocket](/docs/adapters/websocket) upgrade request passed as the initial context:

```ts
const procedure = base.use(requireSession({ auth, dedupe: false }))
```

## Server-Side Calls

In [server-side calls](/docs/client/server-side), pass the incoming request headers as `reqHeaders`. Pass `resHeaders` too if you want to forward the cookies Better Auth sets:

```ts
import { call } from '@orpc/server'

const resHeaders = new Headers()

const user = await call(router.me, undefined, {
  context: { reqHeaders: request.headers, resHeaders },
})
```

Without `reqHeaders`, the request is treated as signed out.
