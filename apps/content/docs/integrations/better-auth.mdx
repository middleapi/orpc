:::warning
This guide assumes familiarity with [Better Auth](https://better-auth.com/). Review the official documentation if needed.
:::

The integration provides middlewares that resolve the Better Auth session and add it to the context, typed from your auth instance.

## Installation

```package-install
npm install @orpc/better-auth@beta better-auth
```

## Setup

The integration requires the [Request Headers Plugin](/docs/plugins/request-headers) and the [Response Headers Plugin](/docs/plugins/response-headers). The middlewares read the request headers from `context.reqHeaders`, and append the cookies Better Auth sets while reading the session, such as a refreshed session cookie or the [cookie cache](https://better-auth.com/docs/concepts/session-management#cookie-cache), to `context.resHeaders`.

```ts
import type { RequestHeadersHandlerPluginContext, ResponseHeadersHandlerPluginContext } from '@orpc/server/plugins'
import { os } from '@orpc/server'
import { RequestHeadersHandlerPlugin, ResponseHeadersHandlerPlugin } from '@orpc/server/plugins'

interface ServerContext extends RequestHeadersHandlerPluginContext, ResponseHeadersHandlerPluginContext {}

const base = os.$context<ServerContext>()

const handler = new RPCHandler(router, {
  plugins: [
    new RequestHeadersHandlerPlugin(),
    new ResponseHeadersHandlerPlugin(),
  ],
})
```

:::info
The `handler` can be any supported oRPC handler, such as [RPCHandler](/docs/rpc/handler), [OpenAPIHandler](/docs/openapi/handler), or a custom one.
:::

## Protected Procedures

`requireSession` adds the session to the context, or throws an `UNAUTHORIZED` error when the request has none. `optionalSession` adds the session, or `null`:

```ts
import { optionalSession, requireSession } from '@orpc/better-auth'
import { auth } from './auth'

const router = {
  me: base
    .use(requireSession({ auth }))
    .handler(({ context }) => context.session.user),

  greeting: base
    .use(optionalSession({ auth }))
    .handler(({ context }) => `Hello, ${context.session?.user.name ?? 'guest'}`),
}
```

`context.session` is `typeof auth.$Infer.Session`, so fields added by plugins or `additionalFields` are typed too. Only a missing session becomes `UNAUTHORIZED`; other errors from `getSession` propagate to oRPC's [error handling](/docs/error-handling).

`auth` also accepts a function, sync or async, that receives the middleware options and input. Use it when the instance lives in the context:

```ts
const procedure = os
  .$context<ServerContext & { auth: typeof auth }>()
  .use(requireSession({ auth: ({ context }) => context.auth }))
```

## Permissions

Both middlewares are [decorated middleware](/docs/middleware), so you can extend them with `.use`. The extension runs after the session is resolved and sees `context.session`. Combined with [metadata](/docs/metadata), this checks the permissions of Better Auth's [access control](https://better-auth.com/docs/plugins/admin#access-control) per procedure:

```ts
import { requireSession } from '@orpc/better-auth'
import { defineMeta, ORPCError } from '@orpc/server'
import { auth } from './auth'

type Permissions = Record<string, string[]>

const [permissionMeta, getPermissionMeta] = defineMeta(
  'permission',
  (incoming: Permissions, current) => ({ ...current, ...incoming }),
)

const requirePermission = requireSession({ auth }).use(async ({ context, procedure, next }) => {
  const permissions = getPermissionMeta(procedure)

  if (permissions) {
    const { success } = await auth.api.userHasPermission({
      body: { userId: context.session.user.id, permissions },
    })

    if (!success) {
      throw new ORPCError('FORBIDDEN')
    }
  }

  return next()
})

const router = {
  listUsers: base
    .use(requirePermission)
    .meta(permissionMeta({ user: ['list'] }))
    .handler(async () => {
      // ...
    }),
}
```

Unauthenticated calls get `UNAUTHORIZED` before any permission check. `userHasPermission` comes from the [admin plugin](https://better-auth.com/docs/plugins/admin). With the [organization plugin](https://better-auth.com/docs/plugins/organization), call `auth.api.hasPermission({ headers: context.reqHeaders, body: { permissions } })` instead, which checks the member's role in the active organization.

## Deduplication

When the session middlewares run more than once for the same request, such as chained middlewares or a procedure that [calls](/docs/client/server-side) another one with the same context, the session is looked up only once. The lookup is stored on `context.reqHeaders` and reused while its values stay the same, so each sub-request of a [batch](/docs/plugins/batch), which has its own `reqHeaders`, looks up the session on its own. A failed lookup is not reused.

Set `dedupe: false` to look up the session on every call. Use it when one `reqHeaders` lives much longer than a request, for example when you pass the headers of a [WebSocket](/docs/adapters/websocket) upgrade request as the initial context, so a sign-out or an expired session is noticed on the next call:

```ts
const procedure = base.use(requireSession({ auth, dedupe: false }))
```

## Server-Side Calls

In [server-side calls](/docs/client/server-side), pass the incoming request headers as `reqHeaders`. Pass `resHeaders` too if you want to forward the cookies Better Auth sets:

```ts
import { call } from '@orpc/server'

const resHeaders = new Headers()

const user = await call(router.me, undefined, {
  context: { reqHeaders: request.headers, resHeaders },
})
```

Without `reqHeaders`, the request is treated as signed out.
