```ts crossws
import { createServer } from 'node:http'
import { experimental_RPCHandler as RPCHandler } from '@orpc/server/crossws'
import { onError } from '@orpc/server'

// any crossws adapter is supported
import crossws from 'crossws/adapters/node'

const handler = new RPCHandler(router, {
  interceptors: [
    onError((error) => {
      console.error(error)
    }),
  ],
})

const ws = crossws({
  hooks: {
    message: async (peer, message) => {
      await handler.message(peer, message, {
        /**
         * Provide initial context if needed. The context can be an async function
         * that receives the per-call request as its first argument, and is **not**
         * related to the initial WebSocket upgrade request.
         */
        context: request => ({}),
      })
    },
    close: async (peer) => {
      await handler.close(peer)
    },
  },
})

const server = createServer((req, res) => {
  res.end(`Hello World`)
}).listen(3000)

server.on('upgrade', (req, socket, head) => {
  if (req.headers.upgrade === 'websocket') {
    ws.handleUpgrade(req, socket, head)
  }
})
```

## Client Adapters

| Adapter     | Target                                                                          |
| ----------- | ------------------------------------------------------------------------------- |
| `websocket` | [MDN WebSocket API](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket) |

```ts
import { RPCLink } from '@orpc/client/websocket'

const link = new RPCLink({
  connect: info => new WebSocket('ws://localhost:3000'),
  /**
   * Whether to connect immediately on initialization, instead of waiting
   * for the first call. Reduces latency for the first request.
   *
   * @default false
   */
  connectOnInit: true,

  /**
   * Optional headers to attach to each per-call request.
   * These can be accessed in the server context or via the Request Headers Plugin.
   */
  headers: () => ({})
})
```

:::info
The examples above only show how to configure the link. For examples of creating a typesafe client, see [RPC Link](/docs/rpc/link#typesafe-clients).
:::

### Auto Reconnect

The client adapter has built-in support for reconnecting when the connection is lost. You can configure reconnect behavior with the `reconnect` option when creating the link.

```ts
const link = new RPCLink({
  reconnect: {
    /**
     * Whether to automatically reconnect when the connection is lost.
     *
     * @default false
     */
    enabled: true,

    /**
     * Delay before a (re)connect attempt, in milliseconds.
     *
     * @default info => info.attempt === 1 ? 0 : 2_000
     */
    delay: info => info.attempt === 1 ? 0 : 2_000,

    /**
     * Maximum number of consecutive failed attempts before giving up.
     * When reached, calls waiting for the connection fail, and the next
     * call starts a new reconnect cycle.
     * Should greater than 1
     *
     * @default Infinity
     */
    maxAttempt: Infinity,

    /**
     * Maximum number of connection attempts over the transport's lifetime,
     * successful ones included (see `totalAttempt`).
     * When reached, calls that need a new connection fail instead of connecting.
     *
     * @default Infinity
     */
    maxTotalAttempt: Infinity,

    onClose: {
      /**
       * Whether to proactively reconnect right after the socket closes,
       * rather than waiting for the next call to trigger reconnection.
       * Reduces latency for the next request.
       *
       * @default false
       */
      enabled: false,

      /**
       * Delay before reconnecting after the socket closes, in milliseconds.
       *
       * @default 0
       */
      delay: 0
    }
  }
})
```

### Dead Connections

A connection can die without a `close` event, for example when a laptop sleeps, a phone switches networks, or a router silently drops an idle connection. The socket keeps reporting `OPEN` until the operating system gives up on it, and calls and event iterators on it wait until then. In our tests on Linux, that took Chromium about 7.5 minutes when the client was only listening and about 16 minutes while it was sending. The `ws` package never noticed.

If that is too long for your app, send your own pings and close the socket when the server stops answering:

```ts
const link = new RPCLink({
  reconnect: { enabled: true },
  connect: () => {
    const websocket = new WebSocket('ws://localhost:3000')

    let pingInterval: ReturnType<typeof setInterval> | undefined
    let pongTimeout: ReturnType<typeof setTimeout> | undefined

    websocket.addEventListener('open', () => {
      // Ping on a fixed schedule, even while messages are arriving
      pingInterval = setInterval(() => {
        websocket.send('ping')

        pongTimeout ??= setTimeout(() => {
          websocket.close()
          // A dead connection may not fire `close` for minutes, so fire it now:
          // the link fails pending calls and opens a new connection for the next call
          websocket.dispatchEvent(new CloseEvent('close', { code: 4000, reason: 'Ping timeout' }))
        }, 10_000)
      }, 30_000)
    })

    // Any message proves the connection is alive, not only the pong
    websocket.addEventListener('message', () => {
      clearTimeout(pongTimeout)
      pongTimeout = undefined
    })

    websocket.addEventListener('close', () => {
      clearInterval(pingInterval)
      clearTimeout(pongTimeout)
    })

    return websocket
  },
})
```

Then answer pings on the server:

<CodeGroup>

```ts ws
wss.on('connection', (ws) => {
  ws.addEventListener('message', (event) => {
    if (event.data === 'ping') {
      ws.send('pong')
    }
  })

  handler.upgrade(ws)
})
```

```ts Bun
Bun.serve({
  // ...
  websocket: {
    async message(ws, message) {
      if (message === 'ping') {
        ws.send('pong')
        return
      }

      await handler.message(ws, message)
    },
    // ...
  },
})
```

</CodeGroup>

:::info
- `ping` and `pong` are not RPC messages, so oRPC ignores them on both sides.
- Add the [Retry Plugin](/docs/plugins/retry) so event iterators reconnect and resume from their [last event ID](/docs/async-iterator-object#last-event-id--event-metadata).
- `CloseEvent` and `dispatchEvent` are browser APIs, so this snippet is for browser clients.
- On Cloudflare Durable Objects, answer pings with an auto-response so they don't wake a hibernating object, see [Hibernation Keep-Alive](/docs/integrations/hibernation#keep-alive).
:::

The server has the same problem with clients that disappear. Bun, Deno and uWebSockets.js close them with their built-in `idleTimeout` options. With `ws`, use protocol-level pings, which browsers answer automatically:

```ts
wss.on('connection', (ws) => {
  let isAlive = true
  ws.on('pong', () => {
    isAlive = true
  })

  const interval = setInterval(() => {
    if (!isAlive) {
      // fires `close`, so the handler aborts this socket's calls
      ws.terminate()
      return
    }

    isAlive = false
    ws.ping()
  }, 30_000)

  ws.on('close', () => clearInterval(interval))

  handler.upgrade(ws)
})
```

## Security

When cookies authenticate the socket, verify the `Origin` header before you call `upgrade()` (or accept the connection). Browsers attach cookies to the WebSocket handshake even when another site opens it. `SameSite` is the only limit, and it treats sibling subdomains as the same site. CORS does not apply to WebSockets. Without this check, any website your users visit can open an authenticated socket on their behalf ([Cross-Site WebSocket Hijacking](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/11-Client-side_Testing/10-Testing_WebSockets)).

```ts
const ALLOWED_ORIGINS = new Set(['https://example.com'])

Bun.serve({
  fetch(req, server) {
    if (!ALLOWED_ORIGINS.has(req.headers.get('origin') ?? '')) {
      return new Response('Forbidden', { status: 403 })
    }

    if (server.upgrade(req)) {
      return
    }
    return new Response('Upgrade failed', { status: 500 })
  },
  // ...
})
```

With `ws`, run the same check on the HTTP server's `upgrade` event, before `wss.handleUpgrade()`.

:::info
Non-browser clients can send any `Origin` header, or none. This check protects your users' browsers. It does not replace authentication.
:::
