```ts crossws
import { createServer } from 'node:http'
import { experimental_RPCHandler as RPCHandler } from '@orpc/server/crossws'

import crossws from 'crossws/adapters/node'

const handler = new RPCHandler(router, {
  interceptors: [
    onError((error) => {
      console.error(error)
    }),
  ],
})

const ws = crossws({
  hooks: {
    message: async (peer, message) => {
      await handler.message(peer, message, {
        /**
         * Provide initial context if needed. The context can be an async function
         * that receives the per-call request as its first argument, and is **not**
         * related to the initial WebSocket upgrade request.
         */
        context: request => ({}),
      })
    },
    close: async (peer) => {
      await handler.close(peer)
    },
  },
})

const server = createServer((req, res) => {
  res.end(`Hello World`)
}).listen(3000)

server.on('upgrade', (req, socket, head) => {
  if (req.headers.upgrade === 'websocket') {
    ws.handleUpgrade(req, socket, head)
  }
})
```

### Idle Timeout

Server handlers answer the client's [keep-alive](#keep-alive) pings automatically. To also drop clients that disappeared without closing their socket, set `idleTimeout`. A socket that sends no message (pings included) for that long is closed with code `1001` (Going Away), and its in-flight calls are aborted. Clients with [auto reconnect](#auto-reconnect) then open a new connection.

```ts
const handler = new RPCHandler(router, {
  /**
   * Close sockets that send no message for this many milliseconds.
   *
   * @default undefined (disabled)
   */
  idleTimeout: 60_000,
})
```

:::warning
Only incoming messages reset the timer, so a client that only receives an event iterator is closed too. Enable [keep-alive](#keep-alive) on every client, with an `interval` well below `idleTimeout`, e.g. the default `30_000` against `60_000`.
:::

:::info
The timer starts on `.upgrade()`, or on the first `.message()` call when you wire messages manually. Bun, Deno and uWebSockets.js have their own built-in `idleTimeout` options, which you can use instead. Do not use it on hibernating Durable Objects, see [Hibernation Keep-Alive](/docs/integrations/hibernation#keep-alive).
:::

```ts
const link = new RPCLink({

  /**
   * Whether to connect immediately on initialization, instead of waiting
   * for the first call. Reduces latency for the first request.
   *
   * @default false
   */
  connectOnInit: true,

   * Optional headers to attach to each per-call request.
   * These can be accessed in the server context or via the Request Headers Plugin.
   */

```

### Auto Reconnect

The client adapter has built-in support for reconnecting when the connection is lost. You can configure reconnect behavior with the `reconnect` option when creating the link.

```ts
const link = new RPCLink({
  reconnect: {
    /**
     * Whether to automatically reconnect when the connection is lost.
     *
     * @default false
     */
    enabled: true,

    /**
     * Delay before a (re)connect attempt, in milliseconds.
     *
     * @default info => info.attempt === 1 ? 0 : 2_000
     */
    delay: info => info.attempt === 1 ? 0 : 2_000,

    /**
     * Maximum number of consecutive failed attempts before giving up.
     * When reached, calls waiting for the connection fail, and the next
     * call starts a new reconnect cycle.
     * Should greater than 1
     *
     * @default Infinity
     */
    maxAttempt: Infinity,

    /**
     * Maximum number of connection attempts over the transport's lifetime,
     * successful ones included (see `totalAttempt`).
     * When reached, calls that need a new connection fail instead of connecting.
     *
     * @default Infinity
     */
    maxTotalAttempt: Infinity,

    onClose: {
      /**
       * Whether to proactively reconnect right after the socket closes,
       * rather than waiting for the next call to trigger reconnection.
       * Reduces latency for the next request.
       *
       * @default false
       */
      enabled: false,

      /**
       * Delay before reconnecting after the socket closes, in milliseconds.
       *
       * @default 0
       */
      delay: 0
    }
  }
})
```

### Keep-Alive

A connection can die without a `close` event, for example when a laptop sleeps or a phone switches networks. The socket still reports `OPEN`, so calls and event iterators on it hang. Enable `keepAlive` to detect such half-open connections:

- The link sends a `ping` text frame every `interval`, even while messages are flowing.
- If no message (the server's `pong` or anything else) arrives within `timeout` after a ping, the link closes the connection and fails its pending calls. With [auto reconnect](#auto-reconnect), the next call or `reconnect.onClose` opens a new connection.
- Add the [Retry Plugin](/docs/plugins/retry) so event iterators reconnect and resume from their [last event ID](/docs/async-iterator-object#last-event-id--event-metadata).

```ts
const link = new RPCLink({
  connect: () => new WebSocket('ws://localhost:3000'),
  reconnect: { enabled: true },
  keepAlive: {
    /**
     * Whether to ping the server periodically and treat the connection as lost
     * when nothing arrives in time.
     *
     * @default false
     */
    enabled: true,

    /**
     * Interval between pings, in milliseconds. Keep it below the server's
     * `idleTimeout` and any proxy idle timeout.
     *
     * @default 30_000
     */
    interval: 30_000,

    /**
     * How long to wait after a ping for any message before closing
     * the connection as lost, in milliseconds.
     *
     * @default 10_000
     */
    timeout: 10_000,
  },
})
```

:::info
Keep-alive is opt-in because the server has to answer pings. oRPC's WebSocket handlers do so without any option, but older servers ignore pings, so the link would drop every connection after `interval + timeout`. Update your servers before you enable it on clients.
:::

Pings and pongs are the constant text frames `ping` and `pong`, sent outside the RPC protocol. If you set `encodePeerMessage`/`decodePeerMessage` prefixes, they are prepended to these frames too. Because the frames are constant, a runtime can answer them without running your code. On Cloudflare Durable Objects, this keeps hibernating objects asleep, see [Hibernation Keep-Alive](/docs/integrations/hibernation#keep-alive).

## Security

When cookies authenticate the socket, verify the `Origin` header before you call `upgrade()` (or accept the connection). Browsers attach cookies to the WebSocket handshake even when another site opens it. `SameSite` is the only limit, and it treats sibling subdomains as the same site. CORS does not apply to WebSockets. Without this check, any website your users visit can open an authenticated socket on their behalf ([Cross-Site WebSocket Hijacking](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/11-Client-side_Testing/10-Testing_WebSockets)).

```ts
const ALLOWED_ORIGINS = new Set(['https://example.com'])

Bun.serve({
  fetch(req, server) {
    if (!ALLOWED_ORIGINS.has(req.headers.get('origin') ?? '')) {
      return new Response('Forbidden', { status: 403 })
    }

    if (server.upgrade(req)) {
      return
    }
    return new Response('Upgrade failed', { status: 500 })
  },
  // ...
})
```

With `ws`, run the same check on the HTTP server's `upgrade` event, before `wss.handleUpgrade()`.

:::info
Non-browser clients can send any `Origin` header, or none. This check protects your users' browsers. It does not replace authentication.
:::
