Establish typesafe communication between processes in [Electron](https://www.electronjs.org/) using the [Message Port Adapter](/docs/adapters/message-port). Before you start, we recommend reading the [MessagePorts in Electron](https://www.electronjs.org/docs/latest/tutorial/message-ports) guide.

:::warning
Anything that completes the handshake below can call every procedure in your main-process router, which often has file system or shell access. Iframes and windows opened by your page can post messages to the renderer window too, so keep both of these sender checks:

- The `event.source` check in the [preload script](#preload-process) is what blocks them. The preload sends the IPC message from your main frame, so a `senderFrame` check in the main process alone cannot tell their ports apart from yours.
- The `senderFrame` check in the [main process](#main-process) is defense in depth. It rejects ports sent after the window navigated to foreign content, or from a preload that also runs in other frames. See [Electron's security checklist](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages).

See [Message Port Security](/docs/adapters/message-port#security) for more details.
:::

## Main Process

Listen for a port sent from your app's page, then upgrade it:

```ts
import { onError } from '@orpc/server'
import { RPCHandler } from '@orpc/server/message-port'
import { app, ipcMain } from 'electron'

const handler = new RPCHandler(router, {
  interceptors: [
    onError((error) => {
      console.error(error)
    }),
  ],
})

app.whenReady().then(() => {
  ipcMain.on('start-orpc-server', async (event) => {
    const [serverPort] = event.ports

    /**
     * Defense in depth: only accept ports sent from your app's own origin.
     * `senderFrame` is `null` if the frame has navigated away or been destroyed.
     */
    if (event.senderFrame?.origin !== 'app://bundle') {
      serverPort.close()
      return
    }

    handler.upgrade(serverPort, {
      /**
       * Provide initial context if needed. The context can be an async function
       * that receives the per-call request as its first argument, and is **not**
       * related to the initial upgrade request.
       */
      context: request => ({}),
    })

    serverPort.start()
  })
})
```

:::info
Channel `start-orpc-server` is arbitrary. You can use any name that fits your needs.
:::

## Preload Process

Receive the port from the renderer and forward it to the main process:

```ts
import { ipcRenderer } from 'electron'

window.addEventListener('message', (event) => {
  // Iframes and other windows can post to this window too, so only accept messages the page posts to itself
  if (event.source !== window || event.origin !== window.location.origin) {
    return
  }

  if (event.data === 'start-orpc-client') {
    const [serverPort] = event.ports

    ipcRenderer.postMessage('start-orpc-server', null, [serverPort])
  }
})
```

:::info
Replace `app://bundle` with the origin your app is served from. With `loadFile`, every local file shares the `file://` origin, so these checks cannot tell your page apart from other local files. Prefer serving your app from a [custom protocol](https://www.electronjs.org/docs/latest/tutorial/security#18-avoid-usage-of-the-file-protocol-and-prefer-usage-of-custom-protocols) registered as `standard`, so it gets its own origin.
:::

## Renderer Process

Create a `MessageChannel`, send one port to the preload script, and use the other to initialize the client link:

```ts
import { RPCLink } from '@orpc/client/message-port'

const { port1: clientPort, port2: serverPort } = new MessageChannel()

window.postMessage('start-orpc-client', '*', [serverPort])

const link = new RPCLink({
  port: clientPort,
})

clientPort.start()
```

:::info
The examples above only show how to configure the link. For examples of creating a typesafe client, see [RPC Link](/docs/rpc/link#typesafe-clients).
:::
